# QUOTATION MANAGEMENT & GENERATION SYSTEM

## Product Requirements Document — V1

---

# 1. Project Overview

Build a professional, lightweight web-based quotation generation system for company use.

The application is primarily a **quotation creation and document-generation system**, not a full ERP or CRM.

The system must allow an authorized user to:

1. Log in.
2. Create a quotation.
3. Enter client details.
4. Automatically generate a quotation number.
5. Enter a "Quotation For" heading.
6. Select manpower, equipment, or materials.
7. Add quantities, units, rates/prices, and remarks.
8. Select predefined Terms & Conditions.
9. Create/edit Terms & Conditions while preparing the quotation.
10. Select an authorized signatory.
11. Automatically display the signatory's details and signature.
12. Display the company seal on the right side of the signature area.
13. Preview the completed quotation.
14. Generate PDF.
15. Generate Word/DOCX.
16. Save both files to Google Drive.
17. Automatically organize Google Drive files by year → month → quotation number.
18. Automatically add quotation information to Google Sheets.
19. Allow quotation status tracking through Google Sheets.

The application should have a professional corporate UI and must not generate dummy/demo quotations in production.

---

# 2. Primary Objective

# 9. Quotation Number

The quotation number must be automatically generated.

Example:

SFC-QTN-RUH-2026-001

Next:

SFC-QTN-RUH-2026-002

Next:

SFC-QTN-RUH-2026-003

The system must:

* Generate the number automatically.
* Never ask the user to manually enter it.
* Never create duplicate numbers.
* Use the same quotation number throughout the entire quotation.
* Use the same number for the PDF filename.
* Use the same number for the Word filename.
* Use the same number for the Google Drive folder.
* Use the same number in Google Sheets.

The number must be generated before the quotation is finalized.

The generated quotation number must remain associated with that quotation during editing.

# 30. Google Drive Save Process

When the user clicks:

Save to Google Drive

the application must:

1. Validate the quotation.
2. Ensure a quotation number exists.
3. Generate the final PDF.
4. Generate the final DOCX.
5. Determine quotation year.
6. Determine quotation month.
7. Find/create the year folder.
8. Find/create the month folder.
9. Create a quotation-number folder.
10. Upload the PDF.
11. Upload the DOCX.
12. Get the quotation folder URL.
13. Send quotation metadata to Google Sheets.
14. Display a success message.
15. Provide a link to open the Google Drive folder.

Example:

Quotation:

SFC-QTN-RUH-2026-025

Drive:

Quotation Archive
→ 2026
→ August
→ SFC-QTN-RUH-2026-025
→ SFC-QTN-RUH-2026-025.pdf
→ SFC-QTN-RUH-2026-025.docx

# 33. Security Requirements

Security is important because the application creates official company documents.

The system must:

1. Require login.
2. Never store passwords in frontend source code.
3. Never expose Google credentials.
4. Never expose Google API secrets in browser code.
5. Keep Google Apps Script credentials/configuration server-side.
6. Validate all quotation inputs.
7. Validate quantity.
8. Validate price/rate.
9. Validate client name.
10. Validate quotation number.
11. Reject incomplete quotations.
12. Prevent accidental duplicate quotation numbers.
13. Prevent unauthorized access to administrative configuration.
14. Prevent arbitrary file uploads where not required.
15. Never include test/dummy quotations in production.
16. Never automatically generate fake clients.
17. Never automatically generate fake items.
18. Never automatically generate fake quotation history.
19. Never use placeholder customer data in production.
20. Never silently create a quotation without user action.

---

# 34. No Dummy Data Requirement

This is a strict requirement.

The production application must start with zero quotations unless actual quotations have been created.

Do NOT include:

* Demo quotations
* Fake clients
* Fake companies
* Fake amounts
* Fake quotation numbers
* Fake Google Drive records
* Fake Google Sheet records

During development, test data may be used only in a clearly separated development/test environment.

Production must contain no dummy data.

---

# 35. Prevent Accidental Quotation Creation

A quotation should only be created when the user explicitly selects:

[ Create Quotation ]

and subsequently:

[ Save ]

or:

[ Save to Google Drive ]

Opening the application must NOT create a quotation number automatically.

A temporary draft number may be used internally, but the official quotation number should be committed only when the quotation is saved/finalized according to the selected workflow.

Once an official quotation number has been committed, it must not be reused.

# 37. Error Handling

Do NOT mark the quotation as successfully saved.

"Quotation was generated, but saving to Google Drive failed."

[ Retry Upload ]

Display a warning and provide a retry option.

The system must not create duplicate files unnecessarily when retrying.
