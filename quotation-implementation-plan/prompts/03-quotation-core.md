# Objective

Implement the core quotation entity and its lifecycle: create, edit, view, and list; client information; "Quotation For"; the quotation date; the quotation status; the pricing model wiring; and — the heart of this phase — **automatic, server-authoritative, concurrency-safe quotation-number generation** in the format:

```
SFC/RUH/QTN/YYYY/###          e.g.  SFC/RUH/QTN/2026/003
```

The number is generated by the backend, never typed by the user, never duplicated, and never changed by editing an existing quotation.

# Required Changes

## Quotation numbering — the critical path

Implement in `google-apps-script/src/quotation-number/`:

```
reserve.ts        the locked, idempotent reservation
counters.ts       the Counters sheet repository (year → lastSequence)
idempotency.ts    the Idempotency sheet repository (draftId → quotationNumber)
```

Rules, all mandatory:

1. **Format** — `SFC/RUH/QTN/YYYY/###`. `SFC` = Speed Falcon Company, `RUH` = Riyadh branch, `QTN` = Quotation. All three come from Script Properties (`COMPANY_CODE`, `BRANCH_CODE`, `DOC_TYPE_CODE`), never from inline literals.
2. **Year** — computed from the **quotation date**, never hard-coded, never assumed to be 2026. A quotation dated 2027-01-05 uses the 2027 counter.
3. **Sequence** — automatically incremented, zero-padded to a **minimum** of 3 digits: `001, 002, 009, 010, 099, 100, 101, 1000`. Padding never truncates.
4. **Per-year tracking** — each year has its own counter and starts at `001`. If 2026 ends at `SFC/RUH/QTN/2026/125`, the first 2027 quotation is `SFC/RUH/QTN/2027/001`.
5. **Server authority** — the number is produced only by Apps Script. React must never compute an official number, never read one from `localStorage` or `sessionStorage`, and never derive one from "last row + 1".
6. **Concurrency** — wrap the read-increment-write in `LockService.getScriptLock()` with `tryLock(30000)`, call `SpreadsheetApp.flush()` before releasing, and always release in a `finally`. Failure to acquire returns `NUMBERING_LOCKED`.
7. **Idempotency** — the reservation is keyed by `draftId`. A repeat reservation for the same `draftId` returns the **same** number. This is what prevents a double-clicked Save, a timed-out-but-successful request, or a retry after a Drive failure from burning numbers.
8. **Uniqueness assertion** — before persisting, confirm the number is not already recorded. A duplicate is a hard `DUPLICATE_QUOTATION_NUMBER` error, logged, never silently resolved.
9. **Immutability** — once a quotation has a number, the update path re-reads it from storage and **ignores** any number in the client payload. A client-supplied different number returns `QUOTATION_NUMBER_IMMUTABLE`. Editing never issues a new number.
10. **No number on app open** — per PRD §35, opening the app or the New Quotation form must not reserve anything. Reservation happens only on the explicit finalize/save action.

# Architecture Requirements

- **The backend is the sole authority for quotation numbers.** No exceptions.
- The counter lives in a dedicated `Counters` sheet — **never** derived by scanning the last row of a data sheet, which a deleted, filtered, or re-sorted row would corrupt.
- Reuse `shared/numbering.ts` for formatting and parsing on both sides. Do not write a second formatter in Apps Script.
- Reuse `shared/totals.ts` for the client-side display totals and the server-side recomputation — the same code, which is what makes the mismatch check trustworthy.
- Keep the lock's critical section minimal: counter read, increment, write, flush. No Drive calls, no document generation, no network calls inside the lock.
- Do not add Supabase, PostgreSQL, or any database.
- The quotation form must be composable so Phases 04–06 slot their sections in without restructuring it.

# Security Requirements

- Every quotation action requires a valid session token verified server-side before any sheet access.
- Backdating into a previous year is Admin-only and audited.
- Server-side validation and totals recomputation are mandatory — the client is never trusted with arithmetic (`IMPLEMENTATION_PLAN.md` §8.6).
- Escape leading `=`, `+`, `-`, `@` in any text written to a sheet, so a client name cannot become a live formula.
- Cap every string field's length before writing.
- The response must never include another user's data or internal sheet coordinates.
- Audit every reservation, save, and status change with the actor and the `requestId`.

# Validation Requirements

Reject with `VALIDATION_FAILED` and a per-field message (PRD §36):

- Client Name, Company Name, Address — required, non-empty after trim.
- Quotation For — required, 3–200 characters.
- Quotation Date — required, valid ISO date, within ± 5 years.
- Status — one of the three allowed values.
- Email and phone, when supplied — format-checked.
- The quotation number, when present — must match `^SFC\/RUH\/QTN\/(\d{4})\/(\d{3,})$`.
- On update — the submitted number must equal the stored number, or the request is rejected as `QUOTATION_NUMBER_IMMUTABLE`.
- The same rules run client-side (Zod) and server-side, from `shared/validation-rules.ts`.

# Testing Requirements

**Numbering — all of the following are mandatory:**

- First quotation of a year → `SFC/RUH/QTN/2026/001`.
- Sequential → `001` → `002` → `003`.
- Padding boundaries → `009 → 010`, `099 → 100`, `999 → 1000` (width grows, never truncates).
- Year reset → last of 2026 is `…/2026/125`; the first of 2027 is `…/2027/001`.
- The year comes from the quotation date, not the system clock — a quotation dated 2027 reserved while the clock says 2026 uses the 2027 counter.
- The year is never hard-coded — a test with a mocked 2031 date produces `…/2031/001`.
- Concurrency — N simultaneous reservations against a faked `LockService`/`SpreadsheetApp` yield N distinct, gapless numbers with no duplicates.
- Idempotency — reserving twice with the same `draftId` returns the same number and does not advance the counter.
- Lock failure → `NUMBERING_LOCKED`.
- Duplicate detection → `DUPLICATE_QUOTATION_NUMBER`.
- Immutability — saving an edit preserves the number; a client-supplied different number is rejected.
- Opening the form reserves nothing (PRD §35) — assert no reservation call is made on mount.

**Other:**

- Validation: every rejection rule above.
- Totals: `shared/totals.ts` results match between the client and the server validator; a tampered payload triggers `TOTALS_MISMATCH`.
- Components: the form renders all sections; the number field is read-only with no input element; required and optional client fields are distinguished; the date defaults to today; a `User` cannot backdate into a previous year.
- Services: create, update, get, list, and status-change flows against a mocked API client, including error paths.

# Error Handling

- Codes: `VALIDATION_FAILED`, `TOTALS_MISMATCH`, `QUOTATION_NUMBER_IMMUTABLE`, `DUPLICATE_QUOTATION_NUMBER`, `NUMBERING_LOCKED`, `AUTH_*`, `FORBIDDEN`, `INTERNAL_ERROR`.
- `NUMBERING_LOCKED` shows "System busy, please try again" and the client retries with exponential backoff.
- A reservation that succeeds but is followed by a failed save must leave the number reserved against the `draftId`, so the next attempt reuses it and no number is burned. Test this explicitly.
- Save mutations are **not** auto-retried in the background — only the user retries — so a save can never be silently duplicated.
- Field-level errors map back onto the form inputs; the toast shows the `requestId`.
